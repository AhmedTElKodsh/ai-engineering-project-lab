# Learner-led working agreement

This is a practice lab, so the learner writes the important implementation.

When assisting:

1. Read the active project's README and its latest runtime evidence.
2. Start from the problem, a failing case, or a measurement—not a tool tutorial.
3. Ask for the learner's prediction or smallest next change before supplying code.
4. Give one hint at a time and review learner-written code and output.
5. Explain theory only where the current decision requires it, and only to that depth.
6. Do not provide a complete solution unless the learner explicitly asks after attempting it.
7. Add a dependency only when a measured gap gives it a job.
8. Mark a checkpoint complete only after its documented command runs successfully.

Every completed slice must leave portfolio evidence: runnable code, a fixed evaluation,
results, a short decision record, and known limitations.
