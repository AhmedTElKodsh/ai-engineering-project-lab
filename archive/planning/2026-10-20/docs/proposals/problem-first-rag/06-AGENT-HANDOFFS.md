# Copyable agent handoffs

Use one role at a time. These prompts are task descriptions, not permission to
override AGENTS.md. Paths below are repository-relative. This pack is currently a
proposal. No prompt silently installs it as a second active route.

## A. Independent planning review — usable now

```text
Review docs/proposals/problem-first-rag/ as a proposed replacement teaching sequence.
Read AGENTS.md, project-context.md, learning/route.json, LEARNING.md and the current
roadmap/library map. Run learning_state.py status. Compare documented intent with
actual sequencing; do not describe the old method as purely concept-first.

Check: one cumulative user problem; earlier small useful behavior; adequate theory
before assessment; learner-owned implementation; no serial-hint solution leakage;
explicit fate of moved requirements; stage/library/data-owner consistency; safe
pre-ranking eligibility; separate dev/release/learner-assessment pools; no fake
provider claim presented as live; no progress awarded by planning.

Read only the data needed. All starter cases are exposed development material.
Do not read hidden release answers or alter implementation, state, route, tests,
dependencies or private checkouts. Report defects with file references and the
smallest proposed correction. No commits/pushes or external calls.
```

## B. Adopt the design — only for a separately authorized maintenance task

```text
Task: reconcile the approved problem-first design into this repository's existing
owners. Do this only if the user explicitly authorized adoption; otherwise review
the proposal and stop before mutation.

Read AGENTS.md and project-context.md; inspect Git status and the current candidate
diff. Run uv run python scripts/learning_state.py status; read LEARNING.md, the
active project README and docs/proposals/problem-first-rag/05-COMPARISON-AND-ADOPTION.md.
Preserve all unrelated local work. State validation failure stops routing.

Keep S0-S6 IDs, one route, one ledger and one mentor. Apply the target grouping and
owner map; do not add R-labels to learning state. Preserve every required capability
with a named acceptance owner. Make corpus/framework/private-application decisions
explicit. The planning pack is a dated design record once owners are updated.

Inspect the actual implementation status of the merged improvement plan's P0/P1
integrity prerequisites before trusting new proof; a proposal or matching text is
not a completed repair. Do not expand into unauthorized repairs. Report any blocking
dependency with its exact owner and evidence.

Use the revision-checked writer/refresh workflow, never manual history/derived-view
edits. Do not convert inherited artifacts or maintainer tests into learner credit.
Verify readback and preserve the ledger byte prefix and unrelated observations.
Pilot changed mentor behavior only in an isolated synthetic fixture, then run the
documented maintenance checks on the final candidate and inspect real consumers.

Do not write learner implementation modules, weaken TODO acceptance, call a paid
provider, install copied skill trees, commit or push without separate authorization.
Deliver a reviewable diff, validation results, limits and one accurate resume point.
```

## C. Start or resume tutoring — after adoption, or under the current route

```text
Use the single .agents/skills/project-mentor/SKILL.md and obey AGENTS.md.
Read project-context.md, run uv run python scripts/learning_state.py status, then
read LEARNING.md, the active project contract and only the current case.

Check whether the problem-first proposal has actually been adopted in the canonical
owners. If not, say so and tutor under the current route; do not activate a proposed
R-release or skip a stage requirement because I supplied this prompt.

Frame the current employee's problem, useful outcome and cost of a wrong answer.
Teach unfamiliar vocabulary/mechanisms before assessing them. Show the needed source
excerpt for source comprehension. Ask exactly one meaningful prediction, small
attempt or explanation, then wait for my actual response.

I write the important implementation. Do not scaffold the complete project, finish
my functions/tests, or leak the algorithm through serial hints. Increase assistance
gradually. If I remain stuck after an attempt and useful hints and ask for more help,
supply only the smallest blocker fragment and ask me to adapt/explain it. A full
solution requires an explicit full-solution request and counts as assistance.

Keep supported practice, execution, explanation, independent fresh transfer, delayed
retention, live-provider and deployed evidence separate. The starter fixture and
its dev answers are supplied material, never fresh assessment. Use the current
writer with revision checking and readback only for actual observed evidence.

No provider spending, external writes, commits or pushes are authorized by this
prompt. Leave blocked live gates pending. Begin at the first unresolved checkpoint
and wait after one learner action; do not give me the entire release checklist.
```

## D. Review a learner attempt — use with an actual artifact/output

```text
Act as the existing project mentor. Validate state and the active contract first.
Review the learner artifact and actual command output I supply; if absent, request
one bounded attempt/output rather than inventing it. Check the declared requirement,
support/citation boundary and one meaningful failure case. Explain the earliest
blocking mechanism plainly. Preserve valid evidence separately from confusion.

Do not rewrite the submission. Ask one diagnostic question or offer one bounded
hint, then wait. Record actual assistance and only what the artifact demonstrates.
Inherited code and passing infrastructure tests are not independent learner proof.
```

## E. Evaluate a product release — scoped system evidence, not mastery

```text
Evaluate the declared candidate against its frozen contract and applicable gates.
Verify code/prompt/model/corpus/index/eval identities and dev/release source-family
selectors before running. Do not read or reveal unrelated hidden assessment pools.
If the split is contaminated, name the error and narrow the claim; do not call the
current HR holdout clean without checking its consumers.

Report retrieval separately from support, refusal and leakage; MRR applies only to
answerable items. Unknown citations and valid citations with unsupported statements
must both fail. Hard gates block regardless of average score. Use predeclared paired
comparison/tolerances and label uncertainty honestly. Keep raw errors and at least
one meaningful negative control. No provider cost without explicit budget/target.

This task certifies only observed system behavior on the declared environment and
case set. It does not award learner transfer, retention, live or deployed proof
unless separately observed under their contracts. Do not fix the learner's code.
```

## Minimum context to supply

For plan review: this pack plus its current-owner links. For tutoring: startup
owners, active release/stage contract, one source excerpt/case and the actual
learner attempt. For evaluation: frozen run manifest, applicable gates and the
scoped evaluation pool. Broad repository scans that disclose future solutions or
held-out answers can destroy assessment freshness; keep reads purposeful.
