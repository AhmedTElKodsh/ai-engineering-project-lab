# Candidate progress machinery review

Reviewed 2026-10-12. Scope: `D:/AI Projects/Learning/ai-engineering-project-lab-unified/scripts/learning_state.py`, `tests/test_learning_state.py`, and `learning/PROTOCOL.md`. This is a new scoped review; the earlier blind review remains unchanged. No implementation or evidence files were edited.

The target is fail-closed invalid state and no false learner credit, while retaining the learner's ownership and gradual-hint policy. A machine cannot establish the truth of an assertion from an artifact hash; this review distinguishes that disclosed limitation from evidence relationships it can enforce.

## Verified strengths

The helper rejects maintainer proof, unknown event fields, unknown stages, out-of-order/future timestamps, unsupported assistance values, escaping/missing artifacts, changed proof artifact hashes, and invalid correction target scope. Generated/worked execution and hinted transfer/retention do not count. Prerequisites gate derived readiness, retention requires elapsed time, append checks the previous revision, and writer exclusion plus atomic replacements prevent a torn ledger append. Interrupted derived views fail validation and can be rebuilt from a valid unchanged log. These are useful foundations and the existing tests exercise them.

Ran the existing subset with `uv run --offline --no-sync python -m pytest tests/test_learning_state.py -q -p no:cacheprovider`, with bytecode and pytest plugin auto-loading disabled: **28 passed**. No installation or provider access occurred. Additional synthetic in-memory event sequences were passed to `validate` and `derive` using existing repository artifacts; they did not append events or rewrite views.

## Concrete remaining findings

- **A transfer on the original exercise awards independent transfer credit.** `scripts/learning_state.py:139-150` filters transfer by assistance but never compares its case with execution/explanation practice. Only retention is checked against transfer's case. An execution, explanation, and transfer sharing `case="same-exercise"` pass validation and produce `ready=True`. `learning/PROTOCOL.md:11` promises fresh independent transfer, so this is a relationship the helper currently fails to enforce. Preserve bounded hints as practice, but require a distinct declared transfer case associated with the relevant practice/proof cohort. Add a regression for an original exercise relabelled as transfer; the current fixture generates different cases automatically (`tests/test_learning_state.py:38,45-47`) and cannot catch this.

- **Repairing execution can restore retained ownership from proof obtained before the failure, even on a different tree.** Proof freshness is calculated independently per kind (`scripts/learning_state.py:136-145`). Sequence: execution pass at hour 0, explanation at 1, transfer at 2, retention on a different case at 27, execution fail at 30, repaired execution pass at 31. The result is `retained=True`, reusing transfer at 2 and retention at 27. This also occurs when the repaired execution's tree is `new-config` and the old proofs say `old-config`. The current failure test checks the immediately failed state only (`tests/test_learning_state.py:97-104`), not re-credit after repair. Keep unrelated stage proof and useful old observations, but connect ownership/retention to the current qualifying implementation and its relevant repair epoch. A narrowly repaired failure need not erase all history; it must not silently claim that old transfer or old delayed recall establishes ownership of a materially changed implementation. Explicitly declare and validate which repairs require new independent checks.

- **Session revision and competency proof are not bound to the stage contract revision.** `load` hashes route JSON and ledger bytes only (`scripts/learning_state.py:44-49`). Stage contract and project README files are checked for existence (`:73,77`) but their content does not enter the revision. Editing an existing contract file in place leaves the expected revision valid and current views valid, so a tutor can append from an obsolete contract. Even an explicit route JSON change merely changes the session revision: after refresh, all historical proofs still qualify for the changed stage ID, because events carry no stage/contract revision and `derive` ignores their free-text tree (`:133-157`). The route-edit test proves only stale-session rejection (`tests/test_learning_state.py:186-194`); it does not prove old learner credit is invalidated when requirements change. Include authoritative contract hashes/versions in the snapshot revision and bind credited observations to the relevant stage contract, with an explicit reviewed migration for genuinely unchanged requirements.

- **An explicitly generated explanation is accepted as learner explanation credit.** Explanation has no assistance filter (`scripts/learning_state.py:141-145`), unlike execution, transfer, and retention. A validated sequence with `assistance="generated"` on its passing explanation and an independent transfer returns `ready=True`. The independent transfer proves its declared case, but does not establish that the learner explained the reasoning. The protocol says supplied code is practice rather than ownership and requires actual learner responses before append (`learning/PROTOCOL.md:11,26`). Generated or worked explanatory material should remain assistance/practice; record a separate observed learner explanation after the material is adapted or understood. Hints may remain allowed for formative explanation, but the explanation gate should not count text explicitly declared generated.

- **Malformed route identifiers/schema values can pass validation.** `scripts/learning_state.py:53` accepts `schema_version=true` because Python equality treats `True` as `1`; `:59-65` accepts an empty or whitespace stage ID and does not validate `next_action` as nonblank text. Route JSON also allows unsupported fields while events explicitly reject them. This does not by itself prove fabricated mastery, but it violates the requested fail-closed invalid-state contract and makes `validate` weaker than the later rendering/derivation path. Use exact schema scalar types, nonblank identifiers/actions, and an explicit accepted route field set (or a deliberately versioned extension policy). Extend malformed-input coverage beyond event fields (`tests/test_learning_state.py:138-153`) to the route schema and stage records.

## Interruption, correction, and concurrency limits

No additional defect was established in the tested writer-lock or individual atomic-replacement design. The multi-file transaction limit is accurately disclosed in `learning/PROTOCOL.md:26`; existing interrupted-view and failed-replace tests cover fail-closed recovery. The lock serializes cooperating checkpoint writers, not arbitrary editors of route or evidence files. Contract-revision binding above is therefore especially necessary for stale tutoring sessions.

Corrections preserve ledger observations and affect only the targeted event, as designed. Artifact validation occurs before derivation and checks even invalidated observations; a corrected observation whose original artifact has been edited or removed cannot be recovered simply by appending a correction. This is consistent with strict immutable evidence, but the protocol should explicitly require immutable observation snapshots rather than mutable learner source files, and state that hash corruption requires recovery of the original artifact before normal append/refresh. Treat this as a documented operational boundary, not as permission to silently drop historical records.

The current suite demonstrates mechanics, not absence of false credit across combined transitions. The additional high-value cases are same-exercise transfer, fail/repair followed by reuse of old ownership, differing proof trees, contract-content edits with unchanged route JSON, route requirement changes followed by refresh, generated explanation, and malformed route types. The first four findings affect learner-credit or stale-session behavior and remain despite the 28 passing tests.
